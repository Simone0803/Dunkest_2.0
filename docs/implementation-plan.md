## Not implemented in this pass

- Official calendar integration for Dunkest `Giornata` versus `Turno`; until then,
  unverified fixture proxies are excluded from prediction paths.
- Automatic regular-season/playoffs rule switching; budget and transfer penalty
  remain configurable inputs rather than inferred from a round number.
- New prediction features or a new minutes model: existing walk-forward and
  leakage tests already cover the reviewed pipeline, and no demonstrated gain
  justified additional predictive complexity.
- Live API/scraper integration checks: these require current external service
  access and are not reproducible as part of the local automated suite.


## Follow-up audit hardening (2026-10-15)

- The backtest now passes the carried player roster and coach to the optimizer and to the ex-post oracle, so later rounds are charged for transfers. The player-only oracle metric is separated from the team oracle metric. Backtests starting after GW1 without an explicit starting roster/coach now fail readiness rather than treating the first evaluated round as transfer-free.
- Top-k alternatives differ by player roster only; coach and captain may repeat when they maximize the configured objective.
- Fixture eligibility is verified only when both sides have explicit status evidence. The GW1 gate distinguishes an explicitly ineligible team from a team whose eligibility is unknown.
- Coach forecasts reject unlinked raw NBA schedules for a requested Dunkest gameweek, unless the caller explicitly marks the supplied matchup as verified.
- Minutes and play-probability thresholds are explicit `Settings` options (`optimizer_starter_min_minutes`, `optimizer_sixth_min_minutes`, `optimizer_captain_min_minutes`, `optimizer_min_starter_play_probability`). They are optimization heuristics, not claims about official rules.
- Cache read failures and early truncation of PLUS history now emit warnings; authenticated page diagnostics no longer print page body text. Static opening coach quotes are labeled as a dated fallback and live quotes are identified separately.

Remaining audit items that require further implementation or trusted historical evidence include a single shared live/backtest forecast-context builder, stronger immutable PRE/POST_MATCH archive integration, multi-season lineup decision evaluation with paired uncertainty intervals and fair baselines, player-game proxy-to-official PDK calibration, learned minutes forecasts, uncertainty-scenario optimization, fixture screenshot hashes/human confirmation, and dependency/type/lint/terms-of-service review. No GW1 2026/27 forecast was generated or tuned as part of this pass.

### Shared forecast and proxy calibration follow-up

- Added `pipeline/forecast.py` as the shared forecast/filter contract used by live prediction, the season opener, and walk-forward replay. Historical callers must provide point-in-time inputs explicitly; a missing required historical injury snapshot now fails closed. The backtest intentionally does not reuse current PLUS history when no archived as-of history exists, and this missing prior is an explicit remaining train/serve skew rather than silently backfilled data.
- Live prediction and season-opener flows archive sanitized player market, fixture, injury, coach market, market-value, PLUS and rookie-prior inputs under an immutable `archive/<season>/gwN/pre_match_*` directory with SHA-256 hashes. The writer rejects known realized-target columns. The existing backtest readiness path still requires integration with these archives before they can replace legacy processed snapshot reads.
- Added `scripts/audit_pdk_proxy_calibration.py` and ran it on the official 2025-26 overlay. A chronological split (first 70% of distinct game dates for fit, final 30% for test) compared raw reconstructed PDK against a one-variable affine calibration fitted only on earlier dates. The held-out MAE fell from 0.509 to 0.409; the date-cluster paired bootstrap 95% interval for MAE difference was [-0.108, -0.092]. This is encouraging but is one season and is not sufficient to change production scoring: calibration remains audit-only until replicated on independent seasons and checked for policy/target consistency.
- No learned minutes model or production PDK correction was enabled in this pass. Those changes remain gated on multi-season, strictly chronological validation and evidence that the official label/price/availability inputs are point-in-time clean.


### PRE_MATCH archive replay and multi-season gate (2026-10-15)

- Added `load_pre_match_snapshot`: it selects only immutable, SHA-256-verified PRE_MATCH archives with the required input tables, a verified fixture-to-turn mapping, and capture time strictly before the earliest fixture tipoff. Missing tables, invalid hashes, post-tipoff captures, or missing lineup eligibility fields make the archive unusable. No archive is repaired or reconstructed after the fact.
- `check_backtest_readiness` now prefers this immutable archive for fixture mapping, roster/CR, injuries, and coach-market evidence. Legacy `processed/` snapshots remain a compatibility path only when no valid archive is available; they do not satisfy the new archive-backed replay path.
- Walk-forward replay now obtains the player market, injury snapshot, coach market, and target-gameweek fixture mapping from the same immutable PRE_MATCH archive and results from the separate POST_MATCH archive. The target game's archived mapping is installed before feature generation, and mutable current-week caches are not fallback sources.
- Added `scripts/audit_multiseason_archive_readiness.py` as a read-only gate audit. The 2026-10-15 run found **0 season archive directories and 0 replay-ready gameweeks** under `data/archive`; therefore no multi-season lineup result can currently be certified. This is an evidence gap, not a model failure, and no retrospective snapshots were fabricated.
- Historical market tables must retain valid player/team/role/CR, gameweek, lineup group and status fields; coach markets must carry fixture IDs and opponents. Captures lacking these details fail closed instead of being filled with guessed values.
- The comparison protocol is now explicit: (1) establish a single eligibility mask from verified PRE_MATCH and POST_MATCH archives; (2) evaluate every baseline, ablation and candidate strategy on the exact same season/gameweek keys and candidate universe; (3) report prediction MAE/RMSE/bias separately from selected-lineup realized score and complete-roster coverage; (4) compute paired confidence intervals by resampling gameweeks (not individual players); and (5) reserve the final season as a one-time holdout, never used for feature/weight selection. Any strategy missing an eligible round is excluded from that round for all strategies. No winner can be promoted from proxy outcomes, partial lineup coverage, or an empty/undersized holdout.
- Existing historical lineup comparisons remain exploratory: the strict observed-only audit found only two paired complete ten-player rounds across the available archive, while the sole immutable `data/archives/pre_lock` bundle is 2026/27 GW1 and is marked `incomplete_evidence`. That prospective GW1 holdout remains frozen until 2026-10-23 12:00 UTC and is not used to tune or compare strategies. The archive-backed replay is therefore still blocked on authentic multi-season PRE_MATCH and linked POST_MATCH bundles; existing retrospective tables are not promoted to certified replay inputs.
