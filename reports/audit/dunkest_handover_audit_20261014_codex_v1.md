# Dunkest 2.0 handover audit — 2026-10-14

## Executive status

The repository already contains substantial modeling, optimization, scoring, and audit work. The current local tree includes 43 modified tracked files and hundreds of untracked artifacts; this audit preserved them. `main` is at `14fa06e` and matches `origin/main` (no ahead/behind commits).

The optimizer can produce three structurally feasible forecast lineups. It cannot currently certify them as evidence-based for the target gameweek: the latest GW1 prediction archive was too early for the strict pre-lock window, and historical roster, price, injury, coach, fixture, and realized-score archives needed for a certified backtest are absent. The requested 2025/26 GW1–10 backtest correctly produced no lineup metrics.

## Verified architecture

1. Acquisition and normalization: `data/access.py`, `data/dunkest/*`, and `data/nba/*` collect markets, injuries, fixtures, schedules, NBA logs, and official Dunkest PDK outcomes.
2. Features and predictions: `features/builder.py` builds past-only rolling/history features; `models/predictor.py` trains the standard model; `models/multiseason_training.py` supplies the certified multi-season opening-round trainer; coach and rookie forecasts live in `models/coach.py` and `models/rookie_prior.py`.
3. Roster selection: `optimize/milp.py` builds and independently validates MILP lineups; `pipeline/season_opener.py` orchestrates the opening-week market, forecasts, and three candidates.
4. Evaluation: `backtest/walk_forward.py` masks same-round outcomes before prediction, consumes fixture-linked immutable post-match outcome archives, and calls `backtest/realized_scoring.py`, which refuses incomplete rosters, missing actuals, unverified coach fixtures, and unknown transfer counts. `data/dunkest/fixtures.py` verifies archive hashes, coverage, finite scores, and fixture IDs before the walk-forward runs.

## Completed and verified

- **Multi-season opening model:** both `pipeline/train.py` and `pipeline/season_opener.py` call `train_multiseason_models` for GW1 when enabled. The latest run manifest records official-target training on 93,766 rows through 2024/25; 2025/26 is used as the prior-season feature source, not as a training target.
- **Temporal handling:** rolling official PDK features are lagged; ambiguous duplicate player/date rows fail closed; cross-fitted calibration uses valid OOF predictions. These changes and their tests are present in the working tree. Historical model comparisons report 2025/26 results, but that season has already been inspected by multiple experiments and is not an untouched project-wide holdout.
- **Three forecast candidates:** the 2026-10-14 run in `reports/audit/dunkest_three_workstreams_implementation_20261014_v1.md` lists three feasible lineups with projected team PDK of 230.09, 220.80, and 217.97. These are forecasts, not realized scores. The saved lineups share 8/10 players between ranks 1–2, 8/10 between ranks 1–3, and 7/10 between ranks 2–3. `min_different_players_top_k` currently defaults to 1; these overlaps meet the existing constraint but do not prove strategic portfolio diversification. No out-of-sample lineup advantage is established.
- **Scoring:** Dunkest’s official player feed is used for certified PDK targets and realized player outcomes. The local `pdk_from_boxscore_row` function is explicitly an NBA-boxscore approximation, not the scoring ground truth. The local comparison of that approximation with Dunkest’s 2025/26 official feed found 23,781 matched player-games, MAE 0.522 PDK, and mean official-minus-proxy difference +0.507 PDK. This confirms that the proxy must not be substituted for official realized scores. Coach rules in `rules/coach.py` match the published Dunkest thresholds and credit coefficient table; historical coach results are nevertheless reconstructed from NBA team scores and archived coach credits rather than independently matched to official Dunkest coach-result records. [Dunkest player scoring](https://docs.dunkest.com/regolamento-it/regolamento-fantasy/punteggio-giocatori) · [Dunkest coach scoring](https://docs.dunkest.com/regolamento-it/regolamento-fantasy/punteggio-allenatori)
- **Optimizer/rules:** the current rule page specifies 95 CR for 10 players plus one coach, with 2 centers, 4 forwards, 4 guards, and a maximum of three players from one NBA team including the coach. Existing optimizer smoke tests pass. [Dunkest roster rules](https://docs.dunkest.com/regolamento-it/regolamento-fantasy/creazione-squadra)
- **Coach projection gate:** a code-graph trace found `run_optimize` accepted only the exact `verified_matchup` source. Valid opening-round forecasts with source `verified_matchup_neutral_baseline` were discarded, after which all coach scores were replaced with zero and lineups still generated. The optimizer now accepts both verified sources only when matchup availability is true, and fails closed when no verified coach projection remains. The season-opener also stops when coach inputs/projections are absent instead of manufacturing a zero-point coach pool.
- **Season-opener input integrity:** opening-market parquet caches are reused only when acquisition metadata proves they are within the configured market-age limit; stale, missing-metadata, unreadable, and empty caches trigger a fresh fetch. Player forecasts are checked for finite `expected_pdk` before coach-strength estimation; missing/non-finite scores now stop the run instead of becoming artificial zeroes.
- **Exactly three published lineups:** the solver may return fewer solutions when distinct-roster constraints become infeasible or a later solve times out. The shared `run_optimize` path now requires `optimizer_top_k: 3` and returns only after receiving exactly three valid solutions; partial candidate sets raise before artifact generation. README behavior is aligned with the runtime gate.
- **Historical candidate universe:** a walk-forward audit found that prediction rows came from the post-season stats table and were then intersected with the frozen pregame market, allowing the result feed's player coverage to silently shrink the selectable universe. Predictions now start from every validated pregame market row; the official Dunkest result feed is used only to construct realized outcomes. Outcome fields are excluded from the candidate frame and missing actuals remain missing.
- **Live matchday candidate universe:** the standard data path had the inverse merge direction (`season_stats ← current_market`), so a Lineups-listed player absent from season statistics was silently omitted. Current Lineups entries now define the candidate pool, prices/team/role/availability override secondary stats, unmatched candidates are appended, and invalid identities or missing market fields fail closed. An end-to-end `get_dunkest_data` regression covers the live-only player path.
- **Current-week score isolation and outcome coverage:** `get_dunkest_data` previously copied the current Dunkest result into `pdk`, while `predict_players` falls back to `pdk` if `prior_pdk` is absent. The loader now freezes the season-to-date value as `prior_pdk` before attaching outcomes, keeps the current result in `actual_pdk`, and refreshes cached frames that predate the separated field. A regression verifies the forecast prior remains 10.0 when the same-week result is 13.0. It also leaves `actual_pdk` missing when a player row is absent from the result feed; `_realized_player_scores` then excludes that outcome instead of interpreting it as zero.
- **Coach result validation:** the official rules specify win/loss margin bands, team scoring/defense bonuses, overtime values, and the credit-difference coefficient. The implementation matched those documented values, but previously returned a plausible loss score for a tied or invalid final score. It now returns missing for invalid score outcomes and rejects missing/non-finite pre-game coach credits. The post-match collector excludes those rows from coverage, and historical readiness rejects coach-result archives without finite scores; regressions cover ties, invalid score rows, missing credits, and invalid archives.
- **Walk-forward result provenance:** readiness previously inspected processed result-table files, while `run_walk_forward_backtest` refetched an aggregate Dunkest table and used it for realized player scores. The backtest now consumes the best-covered hash-verified post-match archive after checking its manifest, explicit coverage, finite outcome rows, and fixture IDs; readiness uses the same archive. Partial archives with positive coverage can supply player metrics, while missing outcomes remain absent and incomplete lineups do not contribute team scores. Legacy processed aggregates cannot make a round ready or replace archived outcomes. Removed the backtest's second coach-score reconstruction; it now uses the same archived coach results produced by the post-match collector. The current 2025/26 GW1 CLI remains unready because the required pre-match snapshots and post-match archive are absent.
- **Dynamic substitutions and captain:** a code-path audit of `optimize/milp.py` found that per-turn slot variables were independent. The MILP now permits pre-game slot changes, blocks promotion after a player's game, and permits later demotion. It models the final score multiplier, sixth-man full-score exception, captain bonus loss when benched, and captain reassignment between turns only to players who have not played. Independent validation checks substitution and captain transitions; backtest scoring and artifacts consume the same multiplier and export the captain schedule. A synthetic three-lineup regression verifies distinct players/coaches, legal turn rosters, team limit, and the official 95 CR budget.
- **Coverage visibility:** backtest metrics now report requested/produced weeks, complete lineup scores, and generated/complete/incomplete lineup counts; player forecast metrics report prediction/actual counts and actual coverage. Missing outcomes remain missing rather than becoming partial scores.
- **Top-three comparison:** lineup cards now show the estimated P10–P90 range, captain schedule, and player overlap against each earlier-ranked roster. The same overlap counts are stored in the lineup artifact. The minimum-difference setting remains configurable and unchanged until an out-of-sample study supports a different threshold.
- **Post-match archive path:** the collector now calls the shared immutable snapshot writer instead of duplicating its parquet/hash/manifest logic. It preserves run ID, source files, and coverage audit metadata; tests verify payload hashes, provenance, and rejection of reserved-field overrides. Player actuals come from the official Dunkest feed; coach actuals remain a reconstruction from NBA final logs plus Dunkest rules and are not claimed as independently official.

## Priority issues

### P0 — no certified historical lineup backtest

- **Files:** `data/dunkest/fixtures.py`, `backtest/walk_forward.py`, and missing season/GW archives under `data/processed/`.
- **Observed:** `bash ./run-backtest.sh --config config/backtest.example.yaml --from-gw 1 --to-gw 10` exits 2 with “Backtest non pronto — nessuna metrica lineup prodotta.” For each requested week, fixture mapping/source timestamps, pre-lock roster and CR, injury and coach snapshots, and linked player/coach actuals are missing. Current live market and availability files are fresh, but are not historical substitutes.
- **Impact:** there are no certified historical team-score metrics, baselines, or holdout lineup results. A separate strict proxy report has 409 round keys but only 3 rounds where both strategies have complete 10-player outcomes; historical coach prices, full pre-lock universe, and transfer carry-over are incomplete.
- **Next implementation/data requirement:** retain the new fail-closed behavior and ingest authentic, immutable, fixture-linked pre-lock archives with source timestamps and hashes, plus official player and coach outcomes. Do not fill gaps from today’s market or from the NBA-boxscore PDK proxy.
- **Acceptance:** every evaluated week has complete eligible-pool/lineup evidence, official linked realized scores, known rules and transfers, explicit coverage, and separately reported selection/holdout metrics.

### P1 — historical readiness was measured against the current clock

- **File:** `src/dunkest/data/dunkest/fixtures.py`.
- **Change made:** fixture mapping and archived market/injury/coach timestamps are now checked relative to the relevant historical kickoff/lock. Current live market/availability snapshots remain visible as diagnostics but no longer gate historical replay.
- **Tests:** `tests/test_historical_readiness_time.py` covers old-but-pre-lock archives, post-lock rejection, and replay readiness without current live snapshots.

### P1 — dynamic lineup transitions and scoring could be inaccurate

- **File:** `src/dunkest/optimize/milp.py`.
- **Observed:** the per-turn MILP independently chose every player's slot on every turn. That allowed a player who had already played to move from bench into the starting five, and scoring ignored post-game demotions.
- **Change made:** after a player's game, bench-to-field promotion is prohibited, while field-to-bench demotion is allowed. The MILP models resulting multipliers, including the sixth-man exception and captain-bonus loss when benched. It can reassign captain between turns while preventing appointment of a player who has already played. Captain schedule and score multipliers are saved with the lineup, independently validated, and used by realized scoring. Tests cover transition eligibility and dynamic realized multipliers.

### P1 — realized coach scores lack external outcome verification

- **Files:** `backtest/walk_forward.py`, `rules/coach.py`, and the historical coach market/results archives.
- **Observed:** the formula agrees with the current official regulation and synthetic regression tests, but realized coach scoring is reconstructed from NBA final scores, overtime minutes, and pregame coach CRs. No complete official Dunkest coach-result comparison was found in the required backtest inputs.
- **Next step:** capture or recover fixture-linked official coach results, compare a verified sample against the formula by rule era, and retain fail-closed behavior when overtime or coach-credit evidence is ambiguous.

### P1 — explicit rest-team scoring is not represented in the fixture/model path

- **Files:** `data/dunkest/lineups_browser.py`, `data/dunkest/fixtures.py`, `pipeline/season_opener.py`, `models/predictor.py`, and `optimize/milp.py`.
- **Graph trace:** `lineups_browser.py` reduces calendar batches to matchup labels and `_fixture_observation` persists only fixture teams plus per-side eligibility. `fixtures.py` retains those matchup rows; `_attach_verified_player_matchups` requires each predicted player to resolve to one. The player predictor then emits the normal model forecast, and optimizer multipliers apply captain/bench rules without a rest-team override. In `get_coach_data`, the coach stats-table response is used to map CR, but its `pdk` field is not retained; that endpoint is queried with `weeks=[gameweek]`, so its exact average scope must be verified before using it as a season-to-date rest score.
- **Official rule:** Dunkest explicitly lists teams at rest in the gameweek calendar. Their players and coach receive their current season average in T1; they do not get captain x1.5, while bench scoring is halved. Teams explicitly not on the calendar score zero instead. [Official rest/postponed-game rules](https://docs.dunkest.com/regolamento-it/regolamento-fantasy/partite-rinviate-o-sospese) · [Official team-management rules](https://docs.dunkest.com/regolamento-it/regolamento-fantasy/gestione-squadra)
- **Observed gap:** current fixture schema stores NBA matchups and eligibility flags, but no explicit `rest` versus `not_on_calendar` status or verified pre-lock season-average PDK for players/coaches. The scraper drops non-matchup labels when it builds fixture observations. Inferring rest from a missing matchup would therefore conflate a positive average-score bye with a zero-score team and could distort both projections and captain optimization.
- **Next step:** extend the official calendar capture to preserve its explicit rest/not-on-calendar section and provenance; verify the Dunkest stats endpoint's `pdk` scope, then derive player/coach averages strictly from prior completed Dunkest gameweeks; feed a rest-status and captain-multiplier override through forecast, MILP, validation, and realized-score paths. Until these inputs exist, do not classify missing-matchup teams as resting.

### P1 — no untouched final holdout for the current model policy

- **Files:** `models/multiseason_training.py`, model experiment reports, and future chronological data.
- **Observed:** current expanding-season experiments show multi-season MAE 7.598 versus 7.616 for single-season on 76,094 player-games and 7.779 for a previous-10 baseline. Bias is more negative for multi-season (-0.398 versus -0.119). 2025/26 was previously examined, so these results are historical validation evidence, not a fresh holdout.
- **Acceptance:** freeze model/calibration/ensemble decisions using earlier chronological validation, then evaluate once on a genuinely future period and report bias, interval coverage, and lineup performance.

### P1 — lineup diversity and risk objective lack full-lineup validation

- **Files:** `src/dunkest/optimize/milp.py`, `src/dunkest/config.py`, and missing historical pre-lock/realized lineup archives.
- **Observed:** top-k optimization uses the same configured objective for each candidate and prevents exact/restricted roster overlap; the current default requires only one player to differ. The latest saved candidates differ by only two or three players, with no complete historical round set to compare expected-value, risk-adjusted, or diversification policies on realized outcomes.
- **Next step:** retain the configurable diversity constraint, then compare candidate policies on complete paired walk-forward rounds with the same eligible pool, transfer state, and official realized scores. Choose the production setting from validation rounds and report the untouched holdout separately; do not promote a stronger arbitrary overlap threshold from a single forecast slate.

CBC uses `COIN_CMD`, falling back to the bundled legacy command only when the system command is unavailable. This removes the PuLP 3.3.2 migration warnings in the supported local environment and prepares the model construction for PuLP 4.

- The current report now exposes explicit coverage counts when evaluation rows exist. The present GW1–10 attempt has no evaluable lineup rows at all, so no lineup coverage denominator or score can be certified from this archive.
