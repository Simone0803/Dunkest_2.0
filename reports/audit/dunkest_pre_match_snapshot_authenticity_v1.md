## Conclusions and limits

Non-2026/27 run-level snapshots exist and require their per-run classifications to be reviewed.

Run timestamps and frozen file hashes establish what was saved in a run and that the run predates the mapped fixture date. They do not alone prove the exact retrieval time of each source; that requires source-side metadata copied into the bundle.

New prediction runs now copy any adjacent *.meta.json source metadata files into pre_match_snapshot and hash them in manifest.json.

A valid hash proves that archived bytes match the run manifest; it does not prove the source data itself was correct or available at that exact time. Fixture timestamps are compared by UTC calendar date because some schedule records use date-level midnight placeholders.
